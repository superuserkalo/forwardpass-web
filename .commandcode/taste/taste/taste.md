# Taste
- No em dashes anywhere in site copy, emails, titles, metadata, or comments. Do not substitute semicolons or other punctuation, rewrite the sentence instead. Confidence: 0.95
- Avoids semicolons as a stylistic substitute in marketing/editorial copy, prefers rewriting sentences into shorter declarative ones (e.g. "Important developments. Why they matter. Primary sources."). Confidence: 0.85
- Dislikes default/system typography (Arial, Courier New); wants deliberate, high-quality typefaces chosen for the project (e.g. Newsreader for display, Geist for UI, Geist Mono for technical labels). Confidence: 0.8
- Prefers a minimal, monochrome, editorial aesthetic: restrained alpha, no glows or orbs, quiet layouts. Confidence: 0.75
- Prefers section layouts to be simple (numbered grids, one clear statement) over dense bordered tables or heavy chrome. Confidence: 0.8
- Likes ASCII / sigil-type generative animations as brand elements (e.g. wordmark condensing out of a glyph-noise field) and wants them GPU-accelerated via `vgpu` (WebGPU). Confidence: 0.8
- Hero and motion visuals must be unmistakably legible as their subject: if a viewer "cannot tell what it is", the piece has failed, no matter how clever the abstraction. Abstraction (e.g. glyph-sigil language) is welcome only as brand texture around the subject; when it obscures the subject he demands an actual, literal, full-craft rendering ("build an actual forward pass... make it fucking good"), even drawing the real object with shading, seams, and physics. Quality bar is striking and polished, not merely passable. Monochrome and understated. Confidence: 0.85
- Prefers wordmarks as pure text without an accompanying logo mark, centered in the composition (e.g. removed the FP mark from the footer sigil band and centered the text). Confidence: 0.75
- Workflow: comfortable with committing and pushing directly to `main` once work is validated (build/lint/shader checks), no feature-branch or PR flow; drives the cadence himself with terse go-aheads like "commit and push" / "commit changes and push to main" and expects immediate execution, no ceremony. Confidence: 0.85
- The result must read right visually before he is satisfied; visual correctness in the rendered output is the acceptance bar, not just passing build/lint. Confidence: 0.75
- Batches several sequenced tasks into one message ("commit the changes, then next fix X... When done fixing commit that. Then make it so that...") and expects each task committed separately as its own commit when finished, working through the list in order. When new work is requested while prior work is uncommitted, commit the pending work first as its own commit before starting the new task, and push only at the end of the batch ("commit previous work first and then when you are done push"). Confidence: 0.85
- Wants the brand and primary CTA (the collaborate button) kept persistently in view: sticky header, transparent at the top of the page, turning fully opaque but slightly glassy on scroll so the CTA stays "in their face". Confidence: 0.7
- Prefers URL paths that match the feature name semantically (e.g. `/collaborate`, not `/advertise`, for the collaborate feature). Confidence: 0.65
- For topic/feature-list sections, prefers compact, dense, scannable cards over airy editorial treatments: small bordered cards in a tight multi-column grid (two rows, not a long vertical stack), each with a mono topic name, an item count, and tree-connector subtopics (`├──` / `└──`) like a file listing, nothing clickable. He rejected both a plain three-column grid and an asymmetric sticky editorial split before settling on this. Confidence: 0.8
- When a design has missed once or twice, he stops accepting interpretations and drives with a concrete visual reference (a screenshot, a named source like Mobbin), and expects that reference followed closely and literally ("like the screenshot", "nothing stacked vertically, nothing clickable") rather than reinterpreted. Confidence: 0.75
- Wants design decisions grounded in real-world references: explicitly asks for research into how comparable products/sites present things (e.g. web search on how strong newsletters present coverage) and design-inspiration tools before building, and wants the research outcome reported back. Confidence: 0.7
- Responds to end-of-summary flags of unfinished or rejected work with emphatic confirmation ("DO THIS!") and expects flagged items executed as part of the next batch alongside new feedback. Confidence: 0.65
